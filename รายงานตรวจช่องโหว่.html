ตรวจ ณ 22 ส.ค. 2026 (v20.18) · ขอบเขต: โค้ดฝั่งเว็บทั้งหมด + โครง Supabase + นโยบาย RLS

วิกฤต 1. ฐานข้อมูลเปิดให้เขียนแบบไม่ต้องยืนยันตัวตน (anon full access)

ทุกตารางใช้ policy using (true) with check (true) สำหรับ anon key ซึ่งฝังอยู่ในซอร์สหน้าเว็บ — ใครที่เปิดเว็บได้ ก็คัดลอก key แล้วอ่าน/แก้/ลบข้อมูลทุกตารางผ่าน REST ได้โดยตรง (งบ เกิดจริง audit log รหัสผ่าน)
วิธีแก้ (เตรียมไว้แล้วในโปรเจกต์): รัน supabase/auth-setup.sql — เปิด Supabase Auth + RLS ตามบทบาท (is_acct() เขียนได้ทุกตาราง · user เขียนได้เฉพาะแผนกตน · anon อ่าน/เขียนไม่ได้เลย) แล้วให้แอปล็อกอินผ่าน Supa.signIn · มี auth-revert.sql ไว้ย้อนกลับ · นี่คือช่องโหว่ที่ควรปิดก่อนใช้งานจริงข้ามองค์กร

วิกฤต 2. รหัสผ่านเก็บเป็นข้อความล้วน (plaintext) และค่าเริ่มต้นเดาง่าย

ผู้ใช้ทุกคนรหัส 1234 (ผู้กรอกงบ default a) เก็บ plaintext ใน users/user_passwords และ sync ขึ้น Supabase — ประกอบกับข้อ 1 = ใครก็อ่านรหัสทุกคนได้
วิธีแก้: ย้ายไปใช้ Supabase Auth (ทำพร้อมข้อ 1 — รหัสถูก hash โดยระบบ) · ระหว่างรอ: บังคับเปลี่ยนรหัสครั้งแรก + อย่าใช้รหัสร่วมชุดเดียว

สูง 3. การตรวจสิทธิ์ทั้งหมดอยู่ฝั่ง client

assertAccounting / assertAssum / canEditVolume ตรวจใน JavaScript — ผู้ใช้เปิด DevTools เรียก Store.* ตรงๆ หรือยิง REST ข้ามได้ (ล็อก/ส่งแล้ว กันได้เฉพาะคนใช้งานปกติ ไม่กันคนตั้งใจ)
วิธีแก้: RLS ตามบทบาท (ข้อ 1) คือคำตอบจริง — สิทธิ์ต้องบังคับที่ฐานข้อมูล ไม่ใช่หน้าจอ

สูง 4. Sync แบบ "ลบสิ่งที่ไม่มีในเครื่อง" (delete-missing)

pushDiff upsert + ลบแถวที่เครื่องไม่มี — ถ้าเครื่องไหนโหลด db ไม่ครบแล้ว push จะลบข้อมูลบน server (มี guard ตรวจความครบอยู่บางส่วนแล้ว แต่ยังพึ่ง heuristic)
วิธีแก้: คง guard + เพิ่ม: ห้าม push ถ้าจำนวนแถวลดลงเกิน N% จากรอบก่อน · สำรองอัตโนมัติก่อน push ใหญ่ (มี backup มือทำอยู่แล้วใน backup/)

กลาง 5. Audit log แก้ไข/ลบได้จาก client

ตาราง audit เขียนจาก client โดยตรง — ผู้ไม่หวังดี (ข้อ 1) ลบร่องรอยตัวเองได้
วิธีแก้: policy ให้ตาราง audit_logs เป็น insert-only (ห้าม update/delete จากทุก role ยกเว้น service key)

กลาง 6. ข้อมูลทั้งฐานเก็บใน localStorage

เครื่องสาธารณะ/เครื่องร่วม — คนถัดไปเปิดเว็บเจอข้อมูลงบทั้งบริษัท (รวมรหัสผ่านใน db.users)
วิธีแก้: ปุ่ม logout ควรล้าง localStorage · หลังใช้ Auth จริง เก็บเฉพาะ token ไม่เก็บรหัส

ต่ำ · แก้แล้ว ✓ 7. XSS จุดเล็กใน tooltip กราฟ

ชื่อ series/GL ใน tooltip กราฟ (charts.js) แสดงโดยไม่ escape — แก้แล้ว (v20.18) ครอบ UI.esc() ครบ 3 จุด · ส่วนอื่นของแอปครอบ esc() อยู่แล้วทั่วถึง (ตรวจ ~แถวชื่อ/เหตุผล/โน้ตทั้งหมด)
